# Sign All 5주차 강지모 작업 안내

담당 브랜치: `frontend`
작성일: 2026년 11월 11일
상태: 5주차 실행 계획 — 완료 보고서가 아닙니다.

## 공동 목표
프론트엔드 → 백엔드 → AI를 연결해 자기소개서 분석과 질문 생성을 화면에서 확인하는 MVP 1차를 완성합니다. 실제 AI 검증과 demo 검증을 구분합니다. 수어 전체 통합·피드백 고도화는 6주차로 이어갑니다.

## 작업 전 Git 확인
수정 파일이 있으면 먼저 커밋하거나 별도 보관합니다. 깨끗한 작업 트리에서 아래 명령을 실행하세요. 로컬 브랜치가 없으면 switch 대신 git switch --track origin/브랜치명을 사용합니다.

```powershell
git fetch origin
git switch frontend
git merge origin/frontend
git merge origin/main
```

충돌 시 내용을 검토하고 해결한 뒤 진행합니다. backend의 미공유 로컬 병합과 frontend의 UI 패치에 관한 담당별 안내를 먼저 읽으세요.

## 현재 상태
원격 frontend에는 3주차 HTML/JS 초안이 있습니다. 후속 청록색 UI와 처리 중 입력 잠금 등은 김두영 PC의 미커밋 변경입니다. clone이나 pull만으로 받을 수 없으므로 파일 또는 패치를 전달받아야 합니다.

## 작업 순서
1. 최신 main을 frontend에 합치고 김두영에게 로컬 UI 변경을 전달받습니다. 적용 전 git apply --check 등으로 충돌을 확인하고 기존 작업을 보존합니다.
2. 전달받은 frontend/app.js, index.html, style.css, README.md를 검토합니다.
3. backend와 frontend 서버를 실행하여 기업·직무 선택→자기소개서→분석 결과→질문 목록을 브라우저에서 확인합니다.
4. 실제 AI 준비 여부에 맞춰 demo 또는 live임을 정확히 표시합니다. demo를 실제 AI 응답처럼 표시하지 않습니다.
5. 빈 입력, 서버 연결 실패, AI 시간 초과, 세션 만료, 재분석, 처리 중 중복 클릭을 점검합니다.
6. 수어 없음·조회 실패 상태에서도 텍스트 연습을 계속할 수 있는지 확인합니다.
7. 모바일 너비, 키보드 이동, 레이블, 포커스와 로딩 안내를 확인하고 캡처를 남깁니다.
8. UI 코드와 검증 기록을 frontend에 push하고 main 대상 PR을 만듭니다.

## 실행
저장소 루트에서 별도 터미널을 엽니다. Node.js 24를 사용합니다.
- 터미널 1: cd backend 후 npm.cmd start
- 터미널 2: cd frontend 후 node serve.js
- 화면: http://127.0.0.1:5173

## 공통 제출 원칙
- 수정 파일만 선택해 git add하고 커밋·push한 뒤 main 대상 PR을 만듭니다.
- PR에는 변경 내용, 실행 환경·명령, 통과·실패 결과, 미완료 사항을 적습니다.
- .env, 키, 토큰, 개인정보가 포함된 자기소개서와 로컬 DB는 올리지 않습니다.
- 원격에 다른 변경이 있으면 fetch 후 병합하고 재검증합니다. 강제 push하지 않습니다.
- 문서 작성이나 mock 테스트 통과만으로 실제 AI 품질·수어 의미 검증 완료라고 기록하지 않습니다.
