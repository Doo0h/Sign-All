# 한국수어 질문 아바타 연결

영상 동작 추출·로컬 검토·검토 완료 GLB 등록 도구: [수어 동작 준비 도구](../tools/sign-motion/README.md).

현재 서비스에 등록한 검토 완료 수어 모션과 생성 학습 모델은 없습니다. 모든 질문은 준비 중 상태입니다. 별도 개발 도구에서는 CC BY 실제 영상의 ‘운영’ 단어를 CC0 캐릭터의 팔·손에 적용한 미검수 초안을 만들었습니다. [자료와 시험 범위](../tools/sign-motion/REAL-DATA-TRIAL.md)를 참고하세요. 임의 손동작이나 미검수 초안을 질문 번역 결과로 제공하지 않습니다.

## 데이터 준비
1. 사용할 영상·수형 자료에 대해 학습, 동작 추출·변형, 배포 권한을 각각 확인합니다. 사전 링크 이용 가능과 학습·변형 허용은 다릅니다.
2. 질문 전체 의미와 한국수어 표현을 농인 사용자 또는 전문가와 검토합니다. 키워드 나열로 대체하지 않습니다.
3. 영상에서 추출한 손·몸·얼굴 움직임을 보정하고 아바타 골격에 맞춥니다. 정적인 수형 사진은 이동 경로·타이밍·전환 동작을 제공하지 않습니다.
4. 동작·표정이 포함된 자체 완결 GLB를 제작합니다. 외부 텍스처/버퍼, Draco/KTX 압축은 현재 플레이어에서 지원하지 않습니다. 카메라는 모델의 정면(+Z)을 바라봅니다.
5. 한국수어 사용자가 의미와 가독성을 검토한 뒤 정확한 질문 문장에 등록합니다. 질문이 바뀌면 재검토합니다.

## 연결 절차
`frontend/avatars/`에 소문자 영문·숫자·하이픈·밑줄 파일명의 `.glb`를 넣습니다. `backend/src/avatar-catalog.json`에 다음 구조로 등록하고 양쪽 Docker 이미지를 다시 빌드합니다. 아래 값은 형식 설명이며 실제 검토 기록으로 복사하지 마세요.

```json
{
  "questionText": "검토한 질문 원문과 정확히 같은 문장",
  "language": "ksl",
  "status": "draft",
  "reviewedBy": "",
  "reviewedAt": "",
  "rightsConfirmed": false,
  "source": "자료 출처와 허락 기록의 위치",
  "version": "1",
  "assetUrl": "/avatars/question-001.glb",
  "clips": ["question-001"]
}
```

검토와 이용 허락이 실제 완료된 항목만 `reviewed`와 `rightsConfirmed: true`를 사용합니다. 클립 순서대로 재생하며 정지·다시 보기·속도 조절을 지원합니다. 동작 연결부의 언어적 정확성까지 검토해야 합니다. 누락 파일·클립·WebGL 오류 시 텍스트와 단어 사전을 계속 이용할 수 있습니다.

`POST /api/interview/avatar`는 현재 세션의 questionId를 받아 pending 또는 ready를 반환합니다. 브라우저가 보낸 임의 문장이나 다른 세션의 질문으로 조회할 수 없습니다. 준비 중인 항목에는 파일 주소를 노출하지 않습니다.

국립국어원 영상은 개별 이용조건 확인이 필요합니다: https://sldict.korean.go.kr/front/main/copyRightPolicy.do

이 구현은 아바타 재생·연결 기반이며 자동 한국수어 번역, 학습 실행, MP4 생성 기능은 아닙니다.

### VRM 손목 위치 보정 (2026-11-25)

검토 화면의 ‘원본 비율에 맞춰 양손 위치 보정’은 poseWorld의 어깨 중심을 기준으로 손목 위치를 캐릭터에 옮긴다. 원본 대비 모델의 양팔 길이 비율을 프레임별로 구한 뒤 중앙값을 클립 전체에 고정하여 크기 변동을 줄인다. 손별 world 좌표는 서로 다른 원점을 가지므로 양손 간격 계산에 사용하지 않는다.

두 관절 IK로 위팔·아래팔 길이를 보존하며, 기존 손목에서 이동하는 거리는 손마다 최대 6cm로 제한한다. 팔 길이로 도달할 수 없는 목표는 도달 범위 안으로 제한한다. 기존 팔꿈치 방향과 손바닥·손가락 회전 보정은 유지한다. 체크를 끄면 같은 프레임의 기존 배치를 비교할 수 있다.

화면의 mm 수치는 모델 좌표에서 계산한 손목 간격이며 실측 오차나 수어 정확도 점수가 아니다. ‘운영’ 시험 클립 45프레임에서 비율 목표 대비 평균 간격 차이는 보정 전 약 31mm에서 수치 정밀도 수준으로 감소했다. 이는 설정한 기하학적 목표에 맞춘 결과일 뿐, 영상 추출 정확도·손가락 접촉·한국수어 의미 검증을 대신하지 않는다. 다음 검토는 원본과 손가락 접촉·방향을 대조하고 수어 사용자에게 의미 전달을 확인하는 단계다.

### 손가락 회전 연결과 느린 재생 (2026-11-25)

검토 화면에서 ‘손가락 관절 비틀림 연결 보정’을 켜면 두 번째·세 번째 손가락 마디가 앞 마디의 rest 대비 월드 회전 차이를 이어받은 뒤 추출된 뼈 방향을 향하도록 회전한다. 기존 방식은 각 마디를 손바닥 기준으로 독립 계산하여 앞 마디의 비틀림을 잃을 수 있었다. 같은 프레임에서 체크를 꺼 기존 방식과 비교할 수 있다. 0.25배·0.5배 재생은 아바타에 적용되며 원본 영상 플레이어는 독립 재생이다.

관절 방향을 유지하면서 부모 비틀림을 보존하는 기하학 테스트와 실제 VRM의 보정 전후 화면을 확인했다. 손끝 방향에는 여전히 마지막 뼈의 기본 방향 추정이 쓰인다. 손가락 길이 차이, 영상의 가려진 손가락 추정 오류, 피부 메시 충돌·접촉은 이 수정으로 해결되었다고 판정하지 않는다. 손바닥 방향은 기존 추출값을 유지한다. 아직 한국수어 의미 검수 전이다.

### 원본 영상 동기 비교 (2026-11-25)

원본 비교의 동기화 체크를 켜면 아바타가 선택한 프레임의 원본 timestampMs로 영상을 탐색한다. 별도의 영상 재생 시계를 사용하지 않으므로 아바타의 느린 재생과 정지에도 같은 목표 시점을 유지한다. 탐색 중에는 최신 목표를 보관했다가 seeked 이벤트에서 반영한다. 디코딩 지연은 있을 수 있으며 오디오 연속 재생 기능은 아니다. 동기화 중 원본 자체 재생 컨트롤을 숨기고, 체크를 끄면 독립 재생할 수 있다. 영상 없는 경우 동기화는 비활성화된다.

실제 운영 클립으로 0.25배 재생 후 정지, 마지막 프레임, 프레임 이동 및 독립 재생 컨트롤 복원을 브라우저에서 확인했다. 이 기능은 접촉 검토를 위한 비교 도구이며 접촉 자동 수정이나 수어 검수 완료를 의미하지 않는다.

### 프레임별 검토 기록 (2026-11-25)

검토 화면에서 손가락 접촉, 방향, 가림·추출 오류 등을 프레임별 메모로 기록한다. 입력에 초점을 두면 아바타 재생을 정지한다. 메모는 브라우저 localStorage에 자동 저장하며 모델 SHA256, 원본 영상 SHA256, 전체 프레임 타임스탬프를 저장 키로 사용한다. 메모를 비우면 해당 기록을 삭제한다. 브라우저 데이터 삭제 시 사라질 수 있으므로 JSON 내려받기로 보관한다. 저장 불가 환경에서는 실패 안내와 JSON 내보내기를 제공한다.

내보내기에는 원본 출처, 모델·영상 식별값, 프레임 타임스탬프와 메모가 포함되며 status는 draft-unreviewed이다. 기록만으로 동작을 자동 수정하거나 공개 가능한 수어로 승격하지 않는다. 실제 브라우저에서 프레임 이동, 새로고침 복원, 유형 변경, 내보내기 내용, 삭제를 검증했다.

### 손가락 방향 흔들림 완화 (2026-11-25)

손가락 각 마디의 추출 방향에 이전·현재·다음 프레임의 1:2:1 가중 평균을 적용하되 현재 방향에서 회전하는 각도를 최대 6도로 제한한다. 시작·끝 프레임은 변경하지 않고, 길이가 0인 방향은 필터를 건너뛴다. 매번 같은 세 프레임으로 계산하므로 탐색 순서와 재생 속도에 관계없이 결과가 같다. 손바닥·손목 위치와 뼈 길이는 변경하지 않는다. 체크를 끄면 필터 전 방향과 비교할 수 있다.

운영 클립 내부 43프레임 × 양손 15개 마디, 1290개 샘플에서 단위 방향 벡터의 이차 차분 크기 평균은 0.2820에서 0.1465로 약 48% 감소했다. 이는 시간적 변화의 크기이며 정확도 점수가 아니다. 빠른 의도적 동작도 완화될 수 있다. 원본 중간 프레임에는 모션 블러가 있어 손가락 접촉을 확정할 근거가 부족하므로, 접촉 위치를 임의로 강제하지 않았다. 손끝 접촉과 한국수어 의미 검수는 여전히 필요하다.

검증: 방향 유지·길이 보존·6도 제한 및 퇴화 입력 단위 테스트, 실제 45프레임 재생과 모바일 검사. 이 변화는 기하학적 후처리이며 새 모델 학습이 아니다.

### 실제 손끝 뼈 기준 적용 (2026-11-25)

현재 고정된 pixiv VRM의 양손 Distal 노드 아래에는 각각 *_end 자식 노드가 있다. 총 10개 손끝의 기본 월드 방향을 읽어 마지막 손가락 마디의 회전 기준으로 사용한다. 기존 앞 마디 방향 추정은 손끝 노드가 없는 경우에만 대체값으로 유지한다. 이 모델은 원래 마지막 뼈들이 거의 일직선이라 외형 변화가 작을 수 있다.

‘실제 손끝 뼈 위치 표시’를 켜면 매 렌더 프레임의 raw 뼈 끝을 읽어 하늘색(왼손)·주황색(오른손) 점으로 표시한다. 점은 가려진 위치도 확인하도록 표면 위에 그려지며, 피부 표면·충돌·접촉 판정이 아니다. 원본 손끝 추출 좌표와 동일한 좌표라고 해석하지 않는다. 10개 끝 노드 탐지, 표시 전환, 선택 프레임 유지와 실제 손 확대 화면을 확인했다.
