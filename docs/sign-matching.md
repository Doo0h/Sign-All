## 1. 공식 수어 자료 제공처 및 이용 조건

### 1.1 조사 대상

| 항목 | 확인 내용 |
|---|---|
| 자료명 | 문화체육관광부_일상생활 수어 |
| 제공기관 | 문화체육관광부 |
| 공식 출처 | https://www.data.go.kr/data/15105152/openapi.do |
| 실제 자료 사전 | 국립국어원 한국수어사전 |
| API 유형 | LINK로 안내됨 |
| 제공 형식 | JSON, XML로 안내됨 |
| 이용 비용 | 무료로 안내됨 |
| 공공데이터포털 이용허락범위 | 제한 없음으로 안내됨 |
| 운영 단계 | 심의 승인 필요로 안내됨 |

> 위 내용은 기존 조사 기록을 기준으로 정리했다. 실제 API 호출 및 운영 신청 과정에서 최신 안내와 세부 조건을 다시 확인한다.

### 1.2 자료 제공 및 이용 조건

공공데이터포털의 공식 안내에 따르면 해당 API는 국립국어원의 일상생활 수어 정보를 제공하며, 수어 명칭, 수형 설명, 이미지, 내용 등의 정보가 안내되어 있다.

국립국어원 한국수어사전의 저작권 정책은 공공데이터포털의 API 이용허락범위와 별도로 확인해야 한다.

기존 조사에서 확인한 사전 저작권 안내:
- 일반 텍스트 및 이미지 자료: 크리에이티브 커먼즈 저작자표시-비영리-변경금지 2.0 대한민국 라이선스 적용 대상
- 저작자 표시가 필요하며 자료를 변경하지 않고 이용해야 함
- 동영상 자료: 개별 영상의 저작권 정책을 별도로 확인해야 함
- 일부 일상생활 수어 영상은 국립국어원이 저작권을 소유하지 않으며, 해당 영상에는 위 크리에이티브 커먼즈 라이선스가 적용되지 않을 수 있음

따라서 공공데이터포털의 이용허락범위와 개별 사전 자료·영상의 이용 조건을 구분한다. 영상 다운로드, 복제, 재배포 및 서비스 내 삽입은 개별 조건을 확인하기 전까지 진행하지 않는다.

이용 방식별 확인 항목:
- 외부 링크 제공: 원문 링크 제공 가능 여부, 출처 표시 및 접근 제한 확인
- 외부 영상 삽입: 임베드 허용 여부, 공식 플레이어·삽입 정책 확인
- 다운로드·저장: 복제 및 저장 허용 여부, 보관 조건 확인
- 재배포: 저작권자 및 라이선스의 재배포 허용 여부 확인
- 서비스 공개: 운영단계 승인·심의 및 서비스 이용 조건 확인

### 1.3 조사 결과 및 미확인 사항

| 조사 항목 | 현재 기록 |
|---|---|
| 공식 제공처 | 확인 |

## 3. 질문과 수어 자료의 연결 기준

실제 생성된 면접 질문을 전달받은 뒤 다음 절차로 조사한다.

1. 전달받은 질문 원문과 질문 출처·버전을 기록한다.
2. 질문 문맥에서 핵심 키워드 3~5개를 선정한다.
3. 각 키워드가 질문에서 어떤 의미로 사용되는지 문맥 정의를 작성한다.
4. 국립국어원 한국수어사전 등 공식 자료에서 키워드 및 관련 표현을 검색한다.
5. 검색 결과의 표제어, 한국어 대응 표현, 의미·용례를 확인한다.
6. 개별 상세 페이지 주소와 자료 식별자를 실제로 확인한 경우에만 기록한다.
7. 영상 제공 여부, 실제 영상 주소, 재생 확인 여부를 서로 구분해 기록한다.
8. 질문 문맥과 사전의 의미·용례를 비교하고 매칭 근거를 작성한다.
9. 의미가 불확실하면 수어에 능숙한 검토자의 확인이 필요하다고 표시한다.
10. 출처 및 이용 조건을 확인한 자료만 백엔드 전달 후보로 분류한다.

### 3.1 매칭 판정 원칙

- 의미 일치: 질문 문맥과 사전 의미·용례가 일치한다고 검토된 경우에만 연결 후보로 확정한다.
- 의미 유사·불확실: 추가 검토 대상으로 남긴다.
- 동음이의어: 질문 문맥과 사전 의미를 비교해 구분한다.
- 복수 표현: 각 표제어·표현을 개별적으로 검토한다.
- 의미 불일치: 연결하지 않는다.
- 자료 없음: 빈 목록 및 미제공 안내 대상으로 분류한다.
- 영상 미확인: 영상 주소를 입력하지 않는다.
- 재생 실패: 자료 존재 여부와 재생 오류를 구분한다.
- 이용 조건 미확인: 서비스 활용을 보류한다.

검색어 일치 또는 백엔드의 `candidate` 상태는 의미 검증 완료를 뜻하지 않는다.

### 3.2 백엔드 연동 기준

현재 조회 API:
`GET /api/signs?keyword=...`

현재 응답 항목:
- `items`
- `matchStatus`
- `notice`

현재 demo에는 실제 수어 자료가 없어 빈 목록을 반환한다.

연동 원칙:
- 검색어와 관련된 후보는 의미 검증 전 상태로 관리한다.
- 의미 검토가 끝나지 않은 후보를 검증 완료 자료처럼 노출하지 않는다.
- 자료가 없으면 빈 목록과 안내 메시지를 사용한다.
- 실제 확인된 출처 페이지와 영상 주소만 전달한다.
- 영상 주소가 있어도 이용 조건이 확인되지 않았다면 서비스 사용을 보류한다.
- 구체적인 상태값 및 응답 구조 변경은 백엔드 담당자와 협의한다.

## 4. 내부 수어 자료 관리 형식

팀 내부 관리 형식은 외부 API의 원본 필드가 아니라 Sign-All에서 사용하는 데이터 구조다.

필수 항목:
- `id`
- `sourceId`
- `term`
- `keywords`

선택 항목:
- `meaning`
- `sourcePageUrl`
- `videoUrl`

추가 조사 기록 권장 항목:
- `sourceName`: 제공 기관 및 자료명
- `checkedAt`: 실제 확인일
- `originalFields`: 실제 원본 응답에서 확인한 항목명과 값
- `licenseStatus`: 이용 조건 확인 상태
- `matchEvidence`: 질문 문맥과 표제어 의미의 매칭 근거
- `reviewerStatus`: 검토자 확인 상태
- `videoAvailability`: 영상 제공 여부
- `playbackStatus`: 재생 확인 결과

기록 규칙:
- `sourceId`는 `sources` 테이블의 내부 출처 ID다. 사전 원본 식별자는 조사 기록의 `originalId`로 별도 관리한다.
- `term`은 실제 사전에서 확인한 표제어만 입력한다.
- `keywords`는 연결 근거가 있는 키워드만 입력한다.
- `meaning`은 실제 사전 설명 또는 검증 가능한 의미 정보가 확인된 경우에만 입력한다.
- `sourcePageUrl`은 실제 상세 페이지 주소를 확인한 경우에만 입력한다.
- `videoUrl`은 실제 영상 주소와 이용 조건을 확인한 경우에만 입력한다.
- 미확인 값을 추정하거나 예시 URL로 채우지 않는다.

## 5. 4주차 작업 범위: 실제 질문 수신 전 준비

4주차에는 AI 담당자로부터 실제 생성 질문을 아직 전달받지 못한 상태이므로, 질문 기반 키워드 선정이나 실제 질문을 이용한 수어 매칭을 완료했다고 기록하지 않는다.

이번 주차 수행 범위:
- 기존 `docs/sign-matching.md`의 조사 기준과 예외 처리 원칙 유지
- 공식 제공처 및 이용 조건의 기존 확인 사항과 미확인 사항 구분
- `data/sign-candidates.md`에 실제 질문 수신 후 작성할 조사표 준비
- 표제어·상세 페이지·영상·재생·이용 조건을 분리 기록할 항목 마련
- 백엔드 전달 전 확인 기준 정리

이번 주차 미수행 항목:
- 실제 생성 질문 기반 핵심 키워드 3~5개 선정
- 실제 생성 질문을 이용한 사전 검색 및 매칭
- 질문 문맥과 수어 용례의 최종 의미 일치 판정
- 신규 영상 URL 및 재생 확인

## 6. 5주차 후속 조사 계획

실제 생성 질문을 전달받으면 다음 작업을 진행한다.

1. 질문 원문과 출처를 기록한다.
2. 질문별 핵심 키워드 3~5개를 선정한다.
3. 공식 사전에서 표제어와 관련 표현을 검색한다.
4. 개별 상세 페이지와 실제 제공 항목을 확인한다.
5. 영상 제공 여부, 실제 영상 주소, 재생 확인 여부를 각각 기록한다.
6. 질문 문맥과 사전 의미·용례를 비교한다.
7. 불확실한 의미는 수어에 능숙한 검토자 확인 대상으로 남긴다.
8. 출처 및 외부 연결·삽입·다운로드·재배포 조건을 확인한다.
9. 확인된 자료만 내부 데이터 구조에 반영하고 백엔드 담당자에게 전달한다.

## 7. 조사 기록 원칙

- 공식 안내에서 확인한 정보와 실제 API 호출 결과를 구분한다.
- 이전 주차 검색 기록과 이번 주차 신규 조사 결과를 구분한다.
- 실제 생성 질문을 전달받기 전에는 질문 기반 조사 완료라고 기록하지 않는다.
