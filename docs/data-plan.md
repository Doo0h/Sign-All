## 원본과 내부 관리 항목

- 원본 필드명·값을 보존하고, 출처별 실제 헤더·응답 키를 확보한 뒤 변환표를 작성합니다.
- 내부 후보: companyId, jobId, signId, sourceId, checkedAt, verificationStatus.
- 위 내부 항목은 팀이 추가하는 정보이며 원본에 존재한다고 가정하지 않습니다.
- 기업의 번호가 고유하고 지속적인 키인지는 원본 검증 후 판단합니다.
- NCS 능력단위는 직무 자체와 구분합니다. 하나의 직무에 여러 능력단위가 연결될 수 있습니다. 코드·개정 정보가 있으면 함께 보존합니다.
- 수어 표제어만으로 고유성을 가정하지 않습니다. 의미·원본 항목 식별자를 확보한 뒤 연결합니다.

## 출처 기록

자료명, 제공기관, 원문 URL, 파일명 또는 요청 경로(인증키 제외), 실제 확인일, 원본 기준일, 이용 조건과 근거 URL, 검증 상태를 관리합니다. 확인일은 팀원이 실제로 확인한 날만 적습니다.

## 누락·중복

- 미확보, 미확인, 원본 필드 없음, 원본 공란을 구분합니다.
- 기업 CSV 공란은 팀이 전달한 공식 안내에 따라 미집계로 표시하며 임의로 채우지 않습니다.
- 기업명 일치는 중복 후보일 뿐입니다. 지역·주소·원본 식별자 등을 비교한 뒤 판단합니다.
- NCS 코드가 같아도 개정판·내용이 다른지 확인한 뒤 중복을 판단합니다.
- 동일 표제어의 다른 의미·수어 표현은 자동 병합하지 않습니다.

## 저장 방식 제안

| 대상 | 초기 관리 제안 | DB 전환 판단 |
|---|---|---|
| 소규모 시연 기업·직무 목록 | 검증 후 JSON/CSV | 검색·수정·공유 요구 확인 |
| 수어 키워드 연결표 | 의미·이용 조건 확인 후 정적 파일 | 다수 항목 관리가 필요할 때 |
| 출처·확인 기록 | 문서 또는 정적 파일 | 관리 기능 필요 시 |
| 자기소개서·답변·AI 결과 | 영구 저장 보류 | 목적·보관 기간·삭제·권한 결정 후 |

기업↔직무, 질문 키워드↔수어의 수동 연결은 연결 근거와 검토 상태를 별도로 기록합니다. 업종만으로 직무를 확정하지 않습니다. 문서 참고 피드백을 공식 NCS 인증 점수나 채용 평가로 표현하지 않습니다.


## 최소 논리 구조 제안 — 3주차 보완

아래는 파일/DB와 독립적인 내부 개념 설계입니다. SQL 테이블 생성이나 데이터 확보 완료를 의미하지 않습니다. 실제 원본에 없는 필드를 원본으로 표시하지 않습니다.

| 대상 | 팀 내부 항목 후보 | 원본 확인 및 연결 규칙 |
|---|---|---|
| Source | sourceId, 자료명, 제공기관, URL, 기준일, checkedAt, 이용 조건, verificationStatus | 기준일·페이지 수정일·실제 확인일 구분 |
| Company | companyId, sourceId, 원본 번호, 실제 확보한 기업 필드 | 번호의 범위·영속성 검증 전 내부 기본키로 확정하지 않음 |
| Job | jobId, 표시명, 출처·분류 참조 | 공식 분류와 팀의 연습 직무를 구분 |
| CompetencyUnit | unitId, sourceId, 확보한 원본 코드·명칭·수준·정의 | 개정 정보가 실제 있으면 보존. 직무 자체와 구분 |
| JobUnitMapping | jobId, unitId, 연결 근거·방식·검토 상태 | 여러 직무↔여러 능력단위. 공식 관계와 팀 검토 관계 구분 |
| SignResource | signId, sourceId, 확보한 표제어·뜻·자료 위치 | 표제어만으로 고유성 판단 금지. 영상 주소는 실제 확인 후 기록 |
| KeywordSignMapping | keyword, 의미·문맥, signId, 검토 상태 | 다수 후보 허용, 문맥 불명확 시 자동 확정 금지 |
| FeedbackReference | referenceId, sourceId, 관련 역량, 문서 위치·쪽수 | 원문 내용과 팀 작성 연습용 기준 구분 |

질문에는 사용한 referenceId를 연결합니다. 질문→답변→피드백은 동일한 연습 맥락에 연결합니다. 임시 sessionId·analysisId·questionId 도입 여부는 별도 결정하며 영구 기록 테이블을 확정하지 않습니다.

기업↔직무를 연결하더라도 실제 채용 관계로 표현하지 않습니다. 사용자 선택 조건 또는 팀이 검토한 연습용 연결임을 명시합니다.

## 정적 파일과 DB 선택 기준

| 기준 | 정적 파일에 유리 | DB에 유리 |
|---|---|---|
| 갱신 | 검토한 소량 자료를 가끔 교체 | 잦은 추가·수정 |
| 조회 | 전체 읽기·단순 검색 | 복합 검색·정렬·관계 조회 |
| 동시 쓰기 | 거의 없음 | 여러 요청이 동시에 변경 |
| 무결성 | 검증 스크립트·리뷰로 관리 | 고유성·참조 관계·트랜잭션 필요 |
| 운영 | 빠른 로컬 공유와 실행 | DB 설정·배포·백업 감당 가능 |

CSV 2,980행이라는 규모만으로 DB를 확정하지 않습니다. 전체 정적 참조자료, 기업·직무만 DB, 참조자료 파일+임시 맥락 저장 등 대안을 비교합니다. 사용자 영구 저장은 목적·보관 기간·삭제·권한 합의 후 결정합니다.
