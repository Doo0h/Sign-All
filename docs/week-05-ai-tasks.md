## 작업 전 Git 확인
수정 파일이 있으면 먼저 커밋하거나 별도 보관합니다. 깨끗한 작업 트리에서 아래 명령을 실행하세요. 로컬 브랜치가 없으면 switch 대신 git switch --track origin/브랜치명을 사용합니다.

```powershell
git fetch origin
git switch ai
git merge origin/ai
git merge origin/main
```

충돌 시 내용을 검토하고 해결한 뒤 진행합니다. backend의 미공유 로컬 병합과 frontend의 UI 패치에 관한 담당별 안내를 먼저 읽으세요.

## 작업 순서
1. docs/ai-prompts.md를 기준으로 코드와 출력 계약을 재확인합니다. backend/src/ai.js 수정은 김두영과 조율합니다.
2. Node 24에서 backend 폴더의 node --test test/ai-prompts.test.js를 실행하고 결과를 기록합니다.
3. 팀과 실제 공급자·모델·비용 상한을 결정합니다. 미정이면 유료 호출하지 않고 준비 조건을 기록합니다.
4. 합의된 환경에서 기존 가상 자기소개서 3개로 실제 모델 분석·질문 시험을 진행합니다. 검증된 참조자료가 없으면 서비스 live 질문 흐름과 가상 자료 모델 시험을 분리합니다.
5. evidence 원문 일치, 없는 경험·성과 생성, 질문 관련성, 질문 1~3개, 출처 ID와 의미를 점검합니다.
6. 프롬프트를 수정했다면 동일 사례로 비교해 개선·악화 여부를 기록합니다.
7. 실제 모델 출력 질문·키워드를 출처와 버전 표시와 함께 수어 담당에게 전달할 문서로 정리합니다. 전달 완료 여부는 실제 공유 후 기록합니다.

## 공통 제출 원칙
- 수정 파일만 선택해 git add하고 커밋·push한 뒤 main 대상 PR을 만듭니다.
- PR에는 변경 내용, 실행 환경·명령, 통과·실패 결과, 미완료 사항을 적습니다.
- .env, 키, 토큰, 개인정보가 포함된 자기소개서와 로컬 DB는 올리지 않습니다.
- 원격에 다른 변경이 있으면 fetch 후 병합하고 재검증합니다. 강제 push하지 않습니다.
- 문서 작성이나 mock 테스트 통과만으로 실제 AI 품질·수어 의미 검증 완료라고 기록하지 않습니다.
