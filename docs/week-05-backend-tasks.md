## 작업 전 Git 확인
수정 파일이 있으면 먼저 커밋하거나 별도 보관합니다. 깨끗한 작업 트리에서 아래 명령을 실행하세요. 로컬 브랜치가 없으면 switch 대신 git switch --track origin/브랜치명을 사용합니다.

```powershell
git fetch origin
git switch backend
git merge origin/backend
git merge origin/main
```

충돌 시 내용을 검토하고 해결한 뒤 진행합니다. backend의 미공유 로컬 병합과 frontend의 UI 패치에 관한 담당별 안내를 먼저 읽으세요.

## 현재 상태와 주의점
원격 backend는 문서 작성 전 888d78f입니다. 김두영 PC의 로컬 backend에는 AI·수어 작업을 합친 096a751이 있고 아직 push되지 않았습니다. UI 4개 파일과 4주차 안내 문서는 미커밋 상태이므로 보존합니다. 이 계획 문서가 원격에 추가되므로 로컬 병합을 원격에 올리기 전에 origin/backend도 합쳐야 합니다.

## 작업 순서
1. 기존 로컬 변경을 보존한 뒤 origin/backend를 로컬 backend에 merge합니다. 로컬 096a751의 병합 내용이 유지되는지 확인합니다.
2. Node.js 24에서 npm.cmd test를 실행합니다. 새 AI 테스트와 기존 서버 테스트 결과를 각각 기록하고 EFAULT 원인을 조사합니다.
3. demo 서버 실행 후 npm.cmd run smoke로 세션→분석→질문→피드백→종료를 확인합니다.
4. AI 담당과 공급자·모델·호출 비용 한도·데이터 처리 조건을 정합니다. 키는 서버 환경변수로만 설정합니다.
5. live 모드 질문 생성에 필요한 기업·직무·능력단위 참조자료와 출처를 확인합니다. 미확보 자료를 verified로 만들지 않습니다.
6. 프론트 담당과 실제 브라우저의 CORS, 요청·응답, 오류 표시, 세션 만료·재분석을 확인합니다.
7. 검증한 통합 변경을 backend에 push하고 main 대상 PR을 만듭니다.

## 공통 제출 원칙
- 수정 파일만 선택해 git add하고 커밋·push한 뒤 main 대상 PR을 만듭니다.
- PR에는 변경 내용, 실행 환경·명령, 통과·실패 결과, 미완료 사항을 적습니다.
- .env, 키, 토큰, 개인정보가 포함된 자기소개서와 로컬 DB는 올리지 않습니다.
- 원격에 다른 변경이 있으면 fetch 후 병합하고 재검증합니다. 강제 push하지 않습니다.
- 문서 작성이나 mock 테스트 통과만으로 실제 AI 품질·수어 의미 검증 완료라고 기록하지 않습니다.
