## 공동 목표
프론트엔드 → 백엔드 → AI를 연결해 자기소개서 분석과 질문 생성을 화면에서 확인하는 MVP 1차를 완성합니다. 실제 AI 검증과 demo 검증을 구분합니다. 수어 전체 통합·피드백 고도화는 6주차로 이어갑니다.

## 작업 전 Git 확인
수정 파일이 있으면 먼저 커밋하거나 별도 보관합니다. 깨끗한 작업 트리에서 아래 명령을 실행하세요. 로컬 브랜치가 없으면 switch 대신 git switch --track origin/브랜치명을 사용합니다.

```powershell
git fetch origin
git switch sign-data
git merge origin/sign-data
git merge origin/main
```

충돌 시 내용을 검토하고 해결한 뒤 진행합니다. backend의 미공유 로컬 병합과 frontend의 UI 패치에 관한 담당별 안내를 먼저 읽으세요.

## 현재 상태
4주차에는 조사 기준과 data/sign-candidates.md 양식이 준비되었습니다. 실제 질문 기반 조사·신규 영상 확보는 미완료로 기록되어 있습니다. AI 브랜치의 docs/sign-keyword-handoff.md는 사람이 만든 모의 질문이며 실제 모델 출력이 아닙니다.

## 작업 순서
1. AI 담당에게 질문·키워드와 생성 방식, 모델, 버전을 요청합니다. main에 아직 없는 문서는 전달받거나 origin/ai에서 읽고 출처를 기록합니다.
2. 실제 출력이 없으면 가상 질문으로 사전 조사를 할 수 있지만 조사표에 가상 질문 기반임을 표시합니다.
3. 핵심 키워드 3~5개를 선정해 공식 수어 사전·제공처에서 후보를 조사합니다.
4. 표제어, 질문 속 의미, 개별 상세 페이지, 실제 영상 제공·주소·재생 여부를 구분해 기록합니다.
5. 링크·삽입·다운로드·재배포 이용 조건을 개별 자료 기준으로 확인합니다. 실제로 확인한 날짜와 근거를 남깁니다.
6. 의미 일치·불확실·자료 없음·영상 미확인을 구분합니다. 필요하면 수어에 능숙한 검토자에게 확인할 항목을 정리합니다.
7. 백엔드·프론트 담당에게 후보 자료와 사용 가능 범위를 전달합니다. 검증되지 않은 자료는 live 데이터로 확정하지 않습니다.

## 데이터 계약 확인
기존 조사표의 sourceId 설명은 백엔드와 대조해 보완해야 합니다. 현재 내부 sourceId는 sources 테이블에 등록하는 내부 출처 ID를 참조합니다. 외부 원본 항목 식별자와 반드시 같지는 않으므로, 원본 ID와 내부 출처 ID를 구분하여 backend 담당과 합의합니다.

## AI에게 보낼 요청문
> Sign-All sign-data 담당이다. 현재 문서는 조사 준비 단계임을 기준으로 시작해 줘. AI 담당에게 받은 질문이 실제 모델 출력인지 모의 질문인지 확인하고 키워드 3~5개의 공식 수어 자료를 조사해 줘. 개별 상세 페이지·영상·재생 여부·출처·이용 조건과 의미 검토 상태를 구분해 기록해 줘. 없는 URL을 만들거나 검색 일치를 의미 검증 완료로 취급하지 마. sourceId는 백엔드의 내부 출처 ID와 외부 원본 ID를 구분해 설명을 보완하고, 미확인 자료는 확정 데이터로 등록하지 마.

## 공통 제출 원칙
- 수정 파일만 선택해 git add하고 커밋·push한 뒤 main 대상 PR을 만듭니다.
- PR에는 변경 내용, 실행 환경·명령, 통과·실패 결과, 미완료 사항을 적습니다.
- .env, 키, 토큰, 개인정보가 포함된 자기소개서와 로컬 DB는 올리지 않습니다.
- 원격에 다른 변경이 있으면 fetch 후 병합하고 재검증합니다. 강제 push하지 않습니다.
- 문서 작성이나 mock 테스트 통과만으로 실제 AI 품질·수어 의미 검증 완료라고 기록하지 않습니다.
