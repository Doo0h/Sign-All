## 4주차 최소 구현 및 완료 기준 — 아직 미구현

| 순서 | 구현 대상 | 확인할 결과 |
|---|---|---|
| 1 | 최소 서버·환경변수·실행 안내 | 팀원이 README에 따라 실행 |
| 2 | POST /api/resume/analyze | 가상 자기소개서→키워드·역량·근거 문장, 형식 검증 |
| 3 | POST /api/interview/questions | 분석 결과+확보한 기업·직무 근거→소수 질문 |
| 4 | 실패 처리 | 빈 입력·잘못된 ID·자료 미준비·AI 형식 오류·시간 초과 |
| 5 | 결과 검토 | 질문 관련성·근거·중복·단정·입력 변경 시 맥락 |
| 6 | 실행 증거 | 요청·응답 예시와 미해결 문제 기록 |

자료 미확보 시 가상 테스트 자료임을 표시합니다. 자기소개서만으로 생성했다면 자기소개서 기반 질문으로 기록하고, 실자료 기반 기업·직무 맞춤 검증을 완료했다고 쓰지 않습니다. 수어·피드백은 계약을 먼저 맞추고 후속 구현·통합합니다.

## 8회 진행 방향

| 회차 | 핵심 활동 | 결과물 |
|---|---|---|
| 1 | 문제 정의·범위·역할 분담 | 문제정의서·MVP 목록 |
| 2 | 제공처·항목 조사·시연 범위 검토 | 활용계획 초안, 미확보 사항 구분 |
| 3 | 원본 샘플 보완·흐름/UI/API/데이터 설계 | 설계 초안·결정 목록 |
| 4 | 자기소개서 분석·질문 생성 구현·검증 | AI 기능 프로토타입·검증표 |
| 5 | 프론트엔드·백엔드·AI 연동 | MVP 1차 |
| 6 | 수어 매칭·텍스트 답변·피드백 통합·자체평가 | MVP 2차·자체평가표 |
| 7 | 외부 자문·사용성 검토·개선 우선순위 | 실제 의견·개선 목록 |
| 8 | 의견 반영·오류 수정·최종 테스트·발표 | 최종 MVP·시연·보고서 |

초기 시연은 직무 1개·소수 기업·검토된 수어 자료로 시작하는 안을 검토합니다. 로그인·면접 기록 조회·새 기능을 필수 범위로 추가하지 않습니다. 외부 검토 일정은 미리 준비합니다.

보고서에는 실제 팀 활동 사진과 설계 문서·저장소 화면을 사용합니다. 설계와 구현, 공식 안내 조사와 실제 샘플 검증을 구분합니다.
