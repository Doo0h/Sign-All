## 2. 코드 반영 범위
- `backend/src/ai.js`: `buildSystemPrompt(kind)`를 추가해 `analyze`와 `questions`별 시스템 프롬프트를 제공. `feedback`은 이번 작업의 본격 변경 대상이 아니므로 기존 공통 지침에 따라 유지.
- `contracts`, `validateAI`, `demo`, `createAI` 어댑터의 JSON 입출력 구조, 모델 파라미터, 서버 ID 할당 경로는 유지. `analysisId`/`questionId`는 서버 소유. 모델은 `references` 또는 URL을 생성하지 않음.
- 분석: evidence 원문 연속 부분 문자열, 근거가 약하면 competencies 빈 배열, 미제공 경험/성과 금지.
- 질문: 1~3개, 참고자료 밖 기업 특성·채용정보·가짜 NCS 금지, 질문당 keywords/허용된 referenceIds만 선택.
- 문서 설명은 요구사항이며 실제 정확한 실행 프롬프트는 `ai.js`가 기준.

## 4. 코드 테스트 실행 여부
- 테스트 코드 작성 완료: `backend/test/ai-prompts.test.js` (가상 3건 고정 mock, 시스템 프롬프트 문자열, 부정 출력).
- **실행하지 못함:** 로컬/원격 실행 머신 연결이 실패했고, 이 검토에서는 실제 백엔드 `npm test` 결과를 확보하지 못했다. 따라서 자동 테스트 통과나 실제 모델 품질 확인을 주장하지 않는다.
- 실행 가능한 환경에서 `cd backend && npm test && npm run smoke` 명령으로 회귀 시험. mock 어댑터만 쓰므로 외부 AI 호출 비용 없음.
- 이후 각 사례로 실제 모델을 호출하려면 공급자·모델·비용 제한·개인정보 정책을 확인한 뒤, 결과의 의미·출처를 사람 검토로 별도 기록해야 한다.

## 5. 실제 AI 시험을 위한 보류 조건
현재 `docs/decisions.md`에는 공급자·모델·비용 범위가 미정으로 기록되어 있으며 `backend/.env.example`의 `AI_API_URL`, `AI_API_KEY`, `AI_MODEL`은 비어 있다. 실제 유료 호출을 수행하지 않았다.

- 팀 합의 필요: API 공급자, 모델명, HTTPS 호환 API 형식, 테스트당/일별 총 비용 상한, 토큰·호출·시간 제한, 데이터 처리 조건 및 동의.
- 서버 설정 후보: `APP_MODE=live`, `AI_API_URL`, `AI_API_KEY`, `AI_MODEL`, `MAX_AI_CALLS_PER_HOUR`, `MAX_AI_CONCURRENT`, `AI_TIMEOUT_MS`.
- `live`에서는 검증된 기업·직무·NCS 자료가 없으면 질문 단계가 차단될 수 있음. 실제 자료 확보·검증 전에는 가상 fixture 시험과 실제 질문 품질 시험을 구분.

## 6. 개선·후속 확인
1. `validateAI`는 evidence 포함과 ID 화이트리스트 등 **형식 중심**으로 검사한다. summary/keywords 및 질문·출처 간 의미 일치는 자동 증명하지 못한다.
2. 질문 입력에는 자기소개서 원문 전체가 아니라 서버가 만든 `analysis`만 포함된다. 따라서 모델은 분석 결과에 없는 구체적 경험을 알 수 없다.
3. `buildSystemPrompt`의 프롬프트 안정성과 응답 비용은 선택 모델의 실제 출력으로 후속 평가해야 한다.
4. 수어 담당 전달용 **가상 질문·핵심 키워드 후보**: [sign-keyword-handoff.md](sign-keyword-handoff.md). 실제 수어 표제어·영상 존재와 의미 일치 확인 전에는 시연 확정 데이터로 사용하지 않는다.
